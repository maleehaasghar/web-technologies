Lecture 2: Web Architecture: Tiers and Layers

How applications are organized

Summary

This lecture explains the difference between tiers and layers and why separation of concerns is important. It compares one-tier, two-tier and three-tier (N-tier) architectures with their advantages and limitations, and shows how to choose the right architecture.

Tiers vs Layers

LayerTier
Logical division of codePhysical separation (different machines)
Can run on the same machineRuns on separate servers or devices
Example: UI layer, logic layerExample: client, app server, database server

Separation of Concerns

Every part of an application should do one job only. For example, the interface shows data, the logic processes it, and the database stores it. This makes the code easier to read, test and change.

One-Tier (Standalone) Architecture

Everything (interface, logic and data) is on a single computer. No network is needed.

Examples: Notepad, MS Word, a calculator, an offline game.

Two-Tier (Client-Server) Architecture

The client (interface and logic) talks directly to a server (usually the database).

Advantages

  • Simple and quick to build
  • Data is stored centrally
  • Good for small applications

Limitations

  • Hard to scale when users increase
  • Logic sits on the client, so updates need to reach every client
  • Less secure because the client talks directly to the database

Three-Tier / N-Tier Architecture

  • Presentation tier: what the user sees (browser).
  • Logic (application) tier: processes the rules.
  • Data tier: database that stores information.

N-tier adds more tiers (for example caching or an API tier) when the system is larger.

Selecting an Architecture (Trade-offs)

FactorWhat to think about
ScalabilityCan it handle more users? Three-tier scales best.
MaintainabilityIs it easy to change one part without breaking the rest?
CostMore tiers mean more servers and effort.
