Lecture 7: CSS Positioning and Stacking

Placing elements exactly where you want

Summary

This lecture explains how elements are placed on a page. It covers normal document flow, the position values (static, relative, absolute, fixed, sticky), offset properties and the containing block, z-index and stacking contexts, and floats with their common layout pitfalls.

Normal Document Flow and Static Positioning

By default every element has position: static. Block elements stack from top to bottom and inline elements flow from left to right. Offset properties (top, left, etc.) do not work on static elements.

Position Values

ValueBehaviour
staticDefault, follows normal flow
relativeMoves from its own normal place, the space is kept
absoluteRemoved from the flow, placed relative to the nearest positioned parent
fixedPlaced relative to the screen, stays when scrolling
stickyNormal at first, then sticks at a set position while scrolling

Offset Properties and the Containing Block

top, right, bottom, left are offset properties. An absolute element is positioned inside its containing block, which is the nearest ancestor with a position other than static. That is why a parent is given position: relative.

z-index and Stacking Contexts

When elements overlap, z-index decides which one is on top. A bigger number appears above a smaller one. z-index works only on positioned elements. A stacking context is a group of elements stacked together, so z-index values are compared inside their own group.

Floats, Clearing and Common Layout Pitfalls

  • float: pushes an element to the left or right and text wraps around it.
  • clear: stops an element from wrapping beside a float.
  • Pitfall: a parent can collapse to zero height when all its children are floated. A clearfix fixes it.
