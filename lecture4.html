Lecture 4: Semantic HTML and Forms

Meaningful structure and user input

Summary

This lecture explains block-level and inline elements, div and span, and semantic elements that give meaning to a page, with their accessibility and SEO benefits. It also covers forms (action, method, input types, select, textarea and button) and the HTML5 client-side validation attributes required, pattern, min and max.

Block-level Elements

Block-level elements create a line break before and after them and take up the full width available. Examples: <div>, <p>, <h1>, <ul>, <table>.

Inline Elements

Inline elements fit within block elements. They do not start on a new line and take only as much width as necessary. Examples: <span>, <a>, <img>, <strong>, <em>.

Block vs Inline Elements

Block elementsInline elements
Start on a new lineStay on the same line
Take the full widthTake only the space they need
Can contain other block or inline elementsCan only contain inline elements

Content Model Categories

The content model answers the question: what content is allowed within a particular container? Block elements belong to the flow category and inline elements to the phrasing category.

div and span

div and span are generic containers. <div>, <p> and <section> usually form larger blocks, while <span>, <a> and <strong> usually sit within text.

Layout Design with Tables

Early web layouts used tables (thead, tbody, tfoot) to divide the page into a header, content and footer.

Div for Layout

<div> is now the preferred method for creating page sections, for example a container div with a header div, a main-content div and a footer div inside it.

Nesting Divs

Div elements can be nested inside each other for more complex layouts, for example a container with a left section and a right section.

Importance of Using Div for Layout

  • More flexible and accessible than tables.
  • Works well with modern web design practices.
  • Easy to style using CSS.

Layout Best Practices

  • Use div for block-level content or sections.
  • Use span for inline text or small elements within other content.
  • Avoid using tables for layout, as it is less responsive and harder to maintain.
  • Tables should be reserved for tabular data (spreadsheets, data tables).

Semantic Elements

Non-semantic elements (div, span) tell nothing about their content. Semantic elements (form, table, article, nav, aside) clearly define their content.

ElementPurpose
headerIntro or branding

Memory trick: think of a newspaper: header, menu, main story, side notes, footer.

Accessibility and SEO Benefits

When meaning is explicit, accessibility, maintainability and machine-readable structure improve. Screen readers understand the page better and search engines rank the content more accurately.

Forms

Forms turn a page into an interaction. The <form> tag is the container for all form elements and defines a form for collecting user input.

action and method

  • action: the URL that receives the submitted data. If it is omitted, the action is the current page.
  • method: the HTTP method used to send data.
  • GET: data is sent through the URL (suitable for small data), e.g. /search?q=html.
  • POST: data is sent in the request body (for secure and large data).
  • target="_blank": the response is displayed in a new window or tab.

The label Element

A label associates text with a form control. Clicking the label focuses the matching input. The for attribute of the label must match the id of the input.

The input Element

The most versatile element for collecting user input. Choose the type that matches the data:

TypeUsed for
textName
emailEmail
passwordPassword
numberMarks
dateDate of birth
checkboxSkills (many choices)
radioGender (one choice)

select, textarea and button

  • select: dropdown selection.
  • textarea: multi-line input.
  • button: submit, reset or action button.

fieldset and legend

Group related controls together with <fieldset> and give the group a title with <legend>. Radio buttons with the same name form one group.

placeholder, name and value

  • placeholder: a hint of the expected value. It disappears when the user starts typing.
  • name: identifies the field when data is submitted to the server. Each field should have a unique name.
  • value: sets the default value of a field and is sent to the server on submit.

Form Submission Process

When a user submits a form, the browser sends the data to the server. The data is collected and sent using the name and value attributes of the input fields.

HTML5 Client-side Validation

AttributeMeaning
requiredThis field cannot be empty. The browser reports a validation error.
patternThe format must match a rule, e.g. SP[0-9]{2}-BSSE-[0-9]{3} accepts SP24-BSSE-001 and rejects SP24-BSSE-01
min / maxNumeric boundaries, e.g. min="0" max="100" accepts 85 and rejects 105

Client validation is helpful (fast feedback), but server validation is essential. Golden rule: client = convenience, server = authority.

Accessible HTML

  • Use meaningful alt text for informative images.
  • Connect <label for="id"> to the matching control.
  • Use fieldset and legend for related controls.
  • Make instructions and validation messages understandable.

HTML5 Is More Than a Logo

  • Semantic: header, nav, main, section, article, aside, footer.
  • Media: audio, video.
  • Forms: email, date, number and built-in constraints.
  • Modern standard: HTML is continuously developed; the Living Standard is current.

HTML5 and CSS Coding-Style Conventions

  • For every container element include both a start tag and an end tag.
  • Use lowercase for all tag names and attributes.
  • Use lowercase for attribute values unless there is a reason for uppercase.
  • Surround attribute values with quotes and omit spaces around the equals sign.
